# AS5600介绍 + FOC应用全解 + 硬件/软件注意事项

## 一、AS5600基础参数与原理
### 1. 核心规格（ams OSRAM原厂）
- **12bit绝对磁编码器**：一圈=4096个计数，单步≈0.0879°，典型精度±0.4°，非接触霍尔测角
- **三种输出**：**I2C(推荐FOC)、PWM、模拟电压(ANALOG)**；I2C默认地址`0x36`，A0/A1引脚可改地址
- **供电**：3.3V/5V双兼容（VDD3V3=3.3V、VDD5V=5V，3.3V模式两脚短接），工作电流≈6.5mA，-40~125℃宽温
- **磁铁要求：径向充磁圆磁铁**（关键！不能轴向充磁），磁场**30~90mT(300~900Gs)**，推荐D8~10mm、厚度2~3mm N35钕铁硼
- **抗杂磁**：均匀外磁场不影响测角，优于霍尔开关、光电编码器（防尘防水）

### 2. 引脚定义（SOIC8）
|引脚|名称|功能|
| ---- | ---- | ---- |
|1|VDD5V|5V供电引脚|
|2|VDD3V3|3.3V供电引脚|
|3|GND|电源地|
|4|OUT|PWM/模拟电压输出|
|5|PGO|状态输出（磁场过强/过弱报警）|
|6|SDA|I2C数据|
|7|SCL|I2C时钟|
|8|DIR|转向控制：GND=顺时针角度增加；VCC=逆时针角度增加|

> A0/A1：I2C地址配置；WP：寄存器写保护，悬空即可（模块板常省略）

## 二、AS5600在FOC无刷电机中的作用
FOC算法**必须实时获取电机电角度θₑ（帕克变换核心输入）**：
$$\boldsymbol{电角度θ_e = 机械角度θ_m × 电机极对数P}$$
1. AS5600实时读取**转子机械绝对角度（0~360°）**，不需要上电回零（绝对编码器优势，对比增量ABZ编码器）
2. 机械角度×极对数 → **电角度**，送入Park/反Park变换，实现定子磁场精准定向，正弦驱动、低噪音
3. 微分机械角度得到**电机实际转速**，用于速度环PID闭环（速度FOC）；位置闭环直接用原始角度做位置PID

### FOC推荐接口选型
✅ **首选I2C数字输出**：抗干扰强、全量程高精度；
❌ 模拟/PWM：长线易受驱动PWM噪声干扰，仅低成本简易方案用。

## 三、FOC硬件接线（I2C方案）
### 1. 标准四线接法（MCU ↔ AS5600模块）
|AS5600|主控(STM32/Arduino)|备注|
| ---- | ---- | ---- |
|VCC|3.3V（优先）/5V|模块自带LDO，3.3V更稳|
|GND|MCU GND+驱动电源GND|**编码器、驱动、MCU必须共地（FOC最关键）**|
|SDA|MCU I2C_SDA|模块自带4.7k上拉，裸片PCB需外挂4.7k上拉至VCC|
|SCL|MCU I2C_SCL|同上|

> DIR：固定GND或VCC，固定计数增减方向，FOC程序里可软件取反角度，不用频繁改硬件

### 2. 磁铁机械安装（FOC故障率最高环节）
1. **同轴居中**：磁铁圆心严格对准AS5600芯片几何中心，径向偏移＜0.3mm；偏位会出现角度非线性、低速抖振
2. **气隙间距0.5~2mm（最优1~1.5mm）**：
   - ＜0.5mm：磁场饱和，MH标志置1，角度卡死；
   - ＞2.5mm：磁场偏弱，角度跳变、FOC低速抖动、无法稳转
3. 磁铁**严格径向充磁**（左右分N/S极），轴向充磁磁铁完全无法正常测角

## 四、FOC软件使用流程（分通用FOC/SimpleFOC两种）
### 方式1：SimpleFOC快速配置（Arduino/STM32，最常用）
```cpp
#include <SimpleFOC.h>
//1.定义AS5600编码器，I2C地址0x36
MagneticSensorAS5600 as5600 = MagneticSensorAS5600(0x36);
BLDCMotor motor = BLDCMotor(7); //7=电机极对数，按实际修改

void setup(){
  as5600.init();//初始化I2C读取
  motor.linkSensor(&as5600);//绑定编码器
  motor.init();
  //关键：FOC零点自动校准（电机空载可自由转动）
  motor.initFOC();
}
void loop(){
  motor.loopFOC();//FOC实时运算（内部自动读角度→算电角度）
  motor.move(2.0);//目标转速2rad/s，速度闭环FOC
}
```
**校准关键：initFOC()自动找电气零点（zero_electric_angle），校准过程电机轻微抖动，务必空载松开轴**

### 方式2：自研STM32 FOC（寄存器读取）
1. **AS5600寄存器**：`RAW_ANGLE(0x0C/0x0D)`，12bit原始值0~4095；
   机械角度 = `(raw_data/4095.0)*360.0°`
2. 换算电角度：`elect_angle = mech_angle * pole_pairs + zero_offset`（zero_offset=电气零点偏移，校准得到）
3. 电角度送入SVPWM、Park变换，闭环PID计算Id/Iq

### FOC三大校准步骤（必做）
1. **零点电气角校准**：FOC上电自动堵转校准/分步注直流找d轴零点，零点错误会出现电机无力、震动、电流偏大
2. **极对数核对**：一圈AS5600角度变化360°，电角度变化=极对数×360°，参数写错转速翻倍/减半
3. **转向修正**：实测角度增减和电机转向相反，DIR改电平或软件`angle=4095-angle`取反

## 五、全场景关键注意事项（硬件+软件+量产坑）
### （一）硬件坑（FOC异常90%源于机械+电源）
1. **共地！共地！**
驱动器大电流地、编码器地、主控地单点共地；驱动母线PWM噪声会串入编码器，导致角度跳变、FOC啸叫、失控。长线I2C加屏蔽线，屏蔽层单端接地。
2. **电源滤波**
AS5600电源引脚就近并联**100nF瓷片+10μF钽电容**，抑制驱动开关电源纹波；纹波＞100mV会造成角度随机漂移。
3. **磁场干扰**
电机定子漏磁＞600Gs会干扰AS5600，编码器远离电机铁芯；漏磁大时加铁氧体屏蔽罩，或增大磁铁磁场至上限。
4. **I2C总线**
- 模块自带上拉电阻不用外挂；自制PCB必须SDA/SCL各4.7k上拉至VCC；
- I2C速率≤100kHz，长引线（＞30cm）降为50kHz，避免通信丢数。

### （二）机械安装禁忌
1. 磁铁歪斜、偏心→角度正弦畸变，FOC低速抖动、力矩不平；
2. 磁铁过强（＞1000Gs）→芯片AGC饱和，PGO引脚报警，角度卡死不动；磁铁太弱＜200Gs→信噪比低、噪声大；
3. 电机震动导致磁铁松动、气隙变化→运行中角度飘移、转速不稳，胶水加固磁铁。

### （三）软件FOC调试要点
1. **采样时机**：AS5600角度读取放在PWM中断起始时刻，和SVPWM同步；错开开关噪声峰值，减少采样误差。
2. **滤波**：原始角度加一阶低通滤波（α=0.05~0.1），滤除高频噪声，但滤波过大造成相位滞后、高速不稳。
3. **零点保存**：校准后的zero_electric_angle存入Flash，下次上电免重复校准（量产必备）。
4. **转速计算**：短周期差分算转速，避免微分噪声过大导致速度PID震荡。

### （四）选型替代提醒
- 高精度FOC（＞10000rpm）：AS5600(12bit)够用；超高精度换MT6701(14bit，带ABZ)；
- 恶劣震动/高温：优选I2C，禁用模拟输出。

## 六、常见故障速查
1. **I2C读不到AS5600**：接线错、地址错误(A0/A1拉高变0x37)、缺上拉、电源未上电；用I2C扫描工具`Wire.scan()`查设备地址
2. **FOC低速抖动、啸叫**：磁铁偏心/气隙超标、零点校准错误、共地不良、电源纹波大
3. **高速丢角度失控**：I2C速率太高、长线无屏蔽、磁场偏弱

AS5600 可以理解成：**一个便宜、好用、适合学习 FOC 的 12bit 磁编码器**。它不是霍尔三相那种粗略位置传感器，而是可以直接读出转子一圈内的绝对机械角度。

## 1. AS5600 是什么？

AS5600 是 ams OSRAM 的**非接触式磁旋转角度传感器**，内部用霍尔阵列检测磁场方向，然后通过 CORDIC 算法算出角度。它测的是**径向充磁磁铁**在芯片正上方旋转时的绝对角度。官方说明它默认输出 0~360°，支持 I²C 配置，也支持模拟输出或 PWM 输出。

它的关键参数大概是：

| 项目     | 说明                    |
| ------ | --------------------- |
| 分辨率    | 12bit，也就是一圈 4096 个位置  |
| 单步角度   | 360 / 4096 ≈ 0.0879°  |
| 接口     | I²C、模拟电压、PWM          |
| I²C 地址 | 固定 7bit 地址 0x36       |
| 供电     | 3.3V 或 5V 模式          |
| 适合     | 旋钮、舵机、低速电机位置检测、FOC 学习 |

注意：**12bit 分辨率不等于 0.0879° 的真实精度**。官方系统特性里给出的 12bit 分辨率下，系统 INL 典型约 ±1°，所以它适合学习和普通控制，但不是高端伺服级编码器。

## 2. AS5600 在 FOC 里起什么作用？

FOC 最核心的一点是：你要知道**转子磁场现在转到哪里了**。
AS5600 测到的是转子的**机械角度 θm**，FOC 需要的是**电角度 θe**。

\theta_e=\operatorname{wrap}*{0,2\pi}\left(p\cdot\left(d\cdot\theta_m-\theta*{offset}\right)\right)

这里：

`θm`：AS5600 读到的机械角度
`p`：电机极对数，比如 7 对极就是 7
`d`：方向，正装为 +1，反向为 -1
`θoffset`：编码器零点和电机磁极零点之间的偏移
`wrap`：把角度限制到 0~2π 范围内

AS5600 只能告诉你“轴转到了多少度”，但是 FOC 还要知道这个角度和电机三相磁场的关系，所以**必须做零点校准**。

## 3. 推荐接法

FOC 里建议优先用 **I²C 读取 RAW_ANGLE**。

AS5600 的 RAW_ANGLE 寄存器地址是 `0x0C`、`0x0D`，ANGLE 寄存器地址是 `0x0E`、`0x0F`。官方说明 RAW_ANGLE 是未缩放、未修改的角度值；ANGLE 是经过缩放后的输出值，而且在 360° 边界附近有 10 LSB 滞回处理。FOC 里更推荐用 RAW_ANGLE。

常见接线：

```text
AS5600        MCU
VCC/VDD   ->  3.3V
GND       ->  GND
SCL       ->  I2C_SCL
SDA       ->  I2C_SDA
DIR       ->  GND 或 VDD
OUT       ->  可不接
```

如果你用 ESP32 / STM32 / GD32 做 FOC，建议：

```c
#define AS5600_ADDR        0x36
#define AS5600_RAW_ANGLE_H 0x0C
#define AS5600_RAW_ANGLE_L 0x0D

uint16_t as5600_read_raw_angle(void)
{
    uint8_t buf[2];

    /*
     * 这里伪代码：
     * 1. I2C 写寄存器地址 0x0C
     * 2. 连续读取 2 字节
     */

    uint16_t raw = ((uint16_t)(buf[0] & 0x0F) << 8) | buf[1];
    return raw;   // 0 ~ 4095
}
```

转换成机械角度：

```c
#define FOC_2PI 6.28318530718f

float as5600_get_mech_angle_rad(void)
{
    uint16_t raw = as5600_read_raw_angle();
    return ((float)raw) * FOC_2PI / 4096.0f;
}
```

FOC 电角度：

```c
float normalize_0_2pi(float x)
{
    while (x >= FOC_2PI) x -= FOC_2PI;
    while (x < 0.0f)    x += FOC_2PI;
    return x;
}

float get_electrical_angle(float theta_m)
{
    const float pole_pairs = 7.0f;        // 按你的电机修改
    const float dir = 1.0f;               // 方向不对就改成 -1
    extern float theta_offset;            // 校准得到

    return normalize_0_2pi(pole_pairs * (dir * theta_m - theta_offset));
}
```

## 4. FOC 中使用流程

### 第一步：确认 AS5600 读数正常

你先不要急着跑闭环 FOC。先用串口打印：

```c
uint16_t raw = as5600_read_raw_angle();
float deg = raw * 360.0f / 4096.0f;

printf("raw=%u, deg=%.2f\r\n", raw, deg);
```

手动转电机轴，看角度是否连续变化。
如果角度乱跳，大概率是磁铁问题、气隙问题、传感器没有对准轴心，或者 I²C 读数不稳定。

### 第二步：确定方向

让电机开环慢慢正转，然后看 AS5600 角度是增加还是减少。

如果你的 FOC 正方向转动时，AS5600 角度反着走，有两个办法：

```c
dir = -1.0f;
```

或者调整 AS5600 的 DIR 引脚。官方说明 DIR 接 GND 时顺时针角度增加，接 VDD 时逆时针角度增加。

### 第三步：校准零点 offset

零点校准是核心。简单做法：

1. 给电机一个固定电角度，比如 `theta_e = 0`。
2. 只给一个小的 `Ud`，让转子吸到这个固定磁场方向。
3. 延时几百 ms，等转子稳定。
4. 读取 AS5600 当前机械角度 `theta_m_align`。
5. 计算 offset。

示例逻辑：

```c
void foc_align_encoder(void)
{
    float align_theta_e = 0.0f;

    /*
     * 输出固定电角度磁场。
     * 简单理解：让定子磁场固定在 theta_e = 0 的方向。
     * 电压不要太大，防止电机发热。
     */
    foc_set_voltage_ud_uq(1.0f, 0.0f, align_theta_e);

    delay_ms(500);

    float theta_m = as5600_get_mech_angle_rad();

    /*
     * 因为 align_theta_e = 0，所以 offset 大概就是 pole_pairs * theta_m。
     */
    theta_offset = normalize_0_2pi(pole_pairs * theta_m);

    foc_set_voltage_ud_uq(0.0f, 0.0f, 0.0f);
}
```

你后面做闭环位置/速度/电流控制时，就用：

```c
theta_e = normalize_0_2pi(pole_pairs * theta_m - theta_offset);
```

## 5. 磁铁安装注意事项，非常重要

AS5600 不是随便拿个磁铁贴上就能用。它需要的是**径向充磁/直径方向充磁**的磁铁，不是普通轴向充磁磁铁。

正确理解：

```text
正确：N/S 在圆片磁铁的左右两边
错误：N/S 在圆片磁铁的上下两个面
```

磁铁要装在电机轴中心，AS5600 芯片要尽量对准磁铁中心。官方评估板文档里给的机械示意气隙是 **0.5~2.5 mm**，并且建议通过 AGC 寄存器辅助判断磁铁对准情况。

磁场强度也不能太弱或太强。官方磁特性给出的正常磁场范围是 30~90 mT，低于检测阈值时会进入磁铁异常状态。

## 6. AS5600 做 FOC 的优缺点

### 优点

它便宜、接线简单、绝对角度输出，不像增量编码器那样每次上电还要找零点。对于你现在学习开环 FOC、闭环速度 FOC、位置控制，非常合适。

### 缺点

它不是高性能电机控制专用编码器。主要问题有几个：

第一，I²C 固定地址是 `0x36`，一个 I²C 总线上直接挂多个 AS5600 会冲突，除非加 I²C 多路复用器。官方数据手册明确写了 7bit 从机地址是 `0x36`。

第二，PWM 输出频率比较低，只有 115 / 230 / 460 / 920 Hz 几档，不太适合高速 FOC 实时角度采样。

第三，它内部有滤波和响应时间。最快滤波设置下 settling time 典型约 0.286 ms，慢滤波可到 2.2 ms。对于 10kHz、20kHz 的电流环来说，角度数据不一定每个 PWM 周期都是新数据。

所以结论是：

| 应用           | AS5600 是否合适     |
| ------------ | --------------- |
| FOC 学习       | 很合适             |
| 低速 BLDC 位置控制 | 可以              |
| 小功率云台/旋钮/舵机  | 可以              |
| 高速电机 FOC     | 不太推荐            |
| 高性能伺服        | 不推荐             |
| 量产高动态电机控制    | 建议换 SPI/ABI 编码器 |

## 7. 你实际调 FOC 时最容易踩的坑

最常见的坑是：**机械角度和电角度搞混**。AS5600 输出的一圈是机械 360°，但电机如果是 7 对极，那么机械转一圈，电角度转 7 圈。

第二个坑是：**没有做 offset 校准**。不校准的话，Park 变换角度错了，电机可能抖动、啸叫、发热，甚至一给电就乱转。

第三个坑是：**方向反了**。方向反了以后，闭环速度控制会变成正反馈，表现就是越控越疯，电机抖动、尖叫、失控。

第四个坑是：**磁铁没对准**。这会导致角度非线性、跳变、噪声大。FOC 对角度非常敏感，角度抖动会直接变成电流抖动和电机声音。

第五个坑是：**用模拟输出做 FOC**。模拟输出还要经过 MCU ADC，ADC 噪声、采样延迟、参考电压误差都会进来。学习可以玩，认真做闭环建议直接 I²C 读 RAW_ANGLE。

## 8. 总结一句话

AS5600 在 FOC 里就是一个**转子机械角度传感器**。你要做的事情是：

```text
AS5600原始值
    ↓
机械角度 θm
    ↓
乘以极对数
    ↓
减去零点偏移 offset
    ↓
得到电角度 θe
    ↓
送给 Park / 逆 Park / SVPWM
```

对于你现在手写 ESP32/STM32 开环和闭环 FOC 来说，AS5600 很适合作为第一块磁编码器。但你后面要做高转速、高动态、低噪声量产级 FOC，就要考虑更快的 SPI 磁编码器或者专用电机控制编码器。


-----
----
这是很多刚接触 FOC 的同学最容易疑惑的地方。

实际上 **AS5600 的 0° 和 FOC 的 0° 不是一个概念**。

## 1. AS5600 的 0° 是什么？

AS5600 内部出厂就有一个角度参考点。

例如：

```text
磁铁转到某个位置
AS5600读数 = 0°

继续转
AS5600读数 = 90°

继续转
AS5600读数 = 180°

继续转
AS5600读数 = 270°
```

这个 0° 由：

* 芯片安装方向
* 磁铁安装方向
* DIR引脚状态

共同决定。

你根本不用知道它物理上在哪里。

对于 FOC 来说：

```text
AS5600显示0°
AS5600显示137°
AS5600显示289°
```

这些都无所谓。

FOC 真正关心的是：

```text
转子磁场
相对于
定子磁场

之间的角度关系
```

---

# 2. FOC 的 0° 是什么？

FOC 的 0° 是：

**转子永磁体磁场与 D 轴重合的位置。**

例如：

```text
          N

          ↑
          │ D轴
          │
          ● 转子

          ↓

          S
```

此时定义：

```text
电角度 θe = 0°
```

但问题来了：

你根本不知道 AS5600 此时显示多少度。

可能：

```text
AS5600 = 23°
```

也可能：

```text
AS5600 = 157°
```

甚至：

```text
AS5600 = 321°
```

都没关系。

所以必须校准。

---

# 3. FOC 里怎么找 0°？

标准方法：

## 第一步

固定一个电角度

例如：

```c
theta_e = 0;
```

---

## 第二步

给一个固定磁场

例如：

```c
Ud = 2V;
Uq = 0;
```

或者

```c
Id = 1A;
Iq = 0;
```

此时：

```text
定子磁场固定不动
```

---

## 第三步

转子自动吸过去

就像磁铁吸铁一样：

```text
      定子磁场

         ↑

         │
         │

      转子N极
         ↑
```

几百毫秒后：

```text
转子稳定
```

---

## 第四步

读取 AS5600

例如：

```c
float mech_angle = as5600_get_angle();
```

结果：

```text
AS5600 = 2.36 rad
```

或者：

```text
AS5600 = 135°
```

---

此时：

```text
转子已经被拉到了

电角度 0°
```

所以：

```text
AS5600 当前角度

就是你的零点偏移
```

保存：

```c
sensor_offset = mech_angle;
```

---

# 4. 以后怎么计算角度？

假设：

```text
校准时

AS5600 = 135°
```

保存：

```c
offset = 135°
```

后来：

```text
AS5600 = 180°
```

则：

```text
机械角度

= 180° - 135°
= 45°
```

即：

```c
theta_m = mech_angle - offset;
```

---

再转换成电角度：

假设电机：

```text
14极

= 7对极
```

则：

```text
θe = 7 × θm
```

即：

```c
theta_e = pole_pairs * theta_m;
```

---

# 5. SimpleFOC 就是这么干的

像 SimpleFOC 里面的：

```c
motor.initFOC();
```

内部就会：

```text
1. 给定固定电角度
2. 拉住转子
3. 读取编码器
4. 保存offset
```

然后以后：

```text
电角度
=
极对数 × (机械角度-offset)
```

---

# 6. AS5600 能不能直接设置 0°？

可以。

AS5600 有：

```text
ZPOS
MPOS
```

寄存器。

可以烧录：

```text
起始角度
结束角度
```

官方叫：

**Zero Position Programming**

但是做 FOC：

## 不建议

因为：

```text
换一个电机
换一个磁铁
换一个安装位置

又得重新烧录
```

很麻烦。

工业上通常做法：

```text
AS5600保持默认

软件记录offset
```

即可。

例如：

```c
float encoder_offset;
```

保存到：

* Flash
* EEPROM
* NVS

上电直接读取。

---

# 7. 实际调试怎么验证？

打印：

```c
printf("AS5600=%f\n", angle_deg);
```

手转电机。

应该看到：

```text
0
20
40
60
80
100
...
```

连续变化。

然后执行：

```c
foc_align_sensor();
```

打印：

```c
offset = 137.5°
```

记录下来。

以后：

```c
theta_e =
pole_pairs *
(angle - 137.5°)
```

就可以正常进行：

```text
Clark
 ↓
Park
 ↓
PID
 ↓
逆Park
 ↓
SVPWM
```

整个 FOC 计算链了。

对于你现在用 ESP32 学习 FOC，我建议先不要碰 AS5600 的 ZPOS/MPOS 烧录功能，直接采用：

```text
AS5600原始角度
      ↓
软件offset校准
      ↓
机械角度
      ↓
电角度
```

这是目前绝大多数开源 FOC（SimpleFOC、ODrive、VESC 等）采用的思路，更方便调试。
