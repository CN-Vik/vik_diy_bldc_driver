结合日志和现象可以直接定位问题根源：
- **“戈登戈登”低频卡顿/转矩脉动**：核心是**电角度与转子永磁体不同步**。从日志能明显看到，`Iq`和`Id`在周期性相互转换（一会儿Iq大、一会儿Id大），总电流幅值接近0.35A，但电流矢量没能稳定落在q轴上，转矩随转子位置周期性波动，就会产生低频顿挫感。
- **“吱吱”高频啸叫**：主要是**电流采样无滤波+PID参数震荡**，ADC噪声直接进入控制环，导致输出电压高频抖动，电机线圈发出音频噪声。

下面按优先级给出分步解决方法，按顺序调试最快见效。

---

## 一、优先解决：电角度零位与方向校准（治“戈登戈登”）
这是当前最核心的问题，90%的低频转矩波动都来源于此。

### 1. 先做堵转验证（5分钟定位问题）
用手紧紧捏住电机轴，不让它转动，临时强制输出固定电压，观察`Id/Iq`表现：
```c
// 临时注释掉PID计算，强制输出固定电压
// pid_out_uq = vfoc_pid_calt_curent_iq(...);
// pid_out_ud = vfoc_pid_calt_curent_id(...);
pid_out_uq = 1.0f;  // q轴给1V电压
pid_out_ud = 0.0f;
```

对照下表判断问题：

| 实测现象 | 问题原因 | 解决方法 |
|---------|----------|----------|
| Iq≈0.047A，Id≈0 | 角度完全正确 | 跳过此步，去调滤波和PID |
| Iq为负值，大小约0.047A | 电角度方向/电流极性反了 | 方案1：极对数改为 `-7`；方案2：电流采样值整体取反 |
| Id很大、Iq接近0 | 零位偏了90° | 电角度增加90°机械角度偏移 |
| Id/Iq都在缓慢来回跳 | 转子没固定住，在微小震动 | 用力捏住轴，或用钳子/胶水固定 |

> 补充判断：给正Uq时，手捏轴能感觉到顺时针转矩；如果是逆时针的力，就说明极性反了。

### 2. 正式零位校准（简单有效）
如果确认是零位偏移，用这个方法精准校准：
1. 保持堵转状态，强制输出 `ud=2.0f, uq=0.0f`
2. 给机械角度加一个偏移量 `ANGLE_OFFSET_DEG`，从0°开始，每次加5°
3. 观察Iq数值，**当Iq最接近0、Id达到最大值时**，这个偏移量就是零位补偿值
4. 写入代码：
```c
// 零位补偿值（机械角度，根据你实测的数值填写）
#define MOTOR0_ANGLE_OFFSET_DEG  23.5f  

elec_angle_rad = get_vfoc_theta_e_rad(mech_angle + MOTOR0_ANGLE_OFFSET_DEG);
```

### 3. 容易忽略的坑：相序对应
如果A、B两相电机线接反，电机也能转，但转矩波动大、噪音大，甚至反转。
- 可以随便交换两根电机相线，再听声音，如果明显变平顺，就是相序错误。

## 二、快速见效：恢复电流滤波+优化PID（治“吱吱”啸叫）
### 1. 恢复相电流低通滤波
你注释掉了电流滤波，ADC的高频开关噪声会直接喂给PID，导致输出电压高频抖动，是“吱吱”声的主要来源。立刻恢复：
```c
/* 相电流低通滤波，alpha=0.1~0.15，兼顾响应速度和噪声抑制 */
adc_m0_val.mtor_ia_curent = low_pass_filter(adc_m0_val.mtor_ia_curent, 0.12f);
adc_m0_val.mtor_ib_curent = low_pass_filter(adc_m0_val.mtor_ib_curent, 0.12f);

// IC由基尔霍夫定律计算得出，不要单独滤波，否则会破坏三相和为0的关系
adc_m0_val.mtor_ic_curent = -adc_m0_val.mtor_ia_curent - adc_m0_val.mtor_ib_curent;
```

### 2. PID参数分步整定
当前参数大概率不合适，容易引发震荡啸叫，按这个顺序调：
1. **先只保留kp，ki、kd设为0**
   - 从5开始慢慢往上加，直到电流阶跃响应快、无超调震荡
   - 2208这种高电阻电机，kp最终一般在15~30之间
2. **再加ki消除静差**
   - 从10开始慢慢加，直到稳态电流精准咬住目标，没有低频波动
   - ki不要太大，否则会出现低频“嗡嗡”震荡，建议初始值20~50
3. **kd保持0即可**，电流环加D项只会放大噪声，几乎没有收益

### 3. 确认输出限幅合理
12V母线SVPWM线性区最大约6.93V，建议`UQ_LIMIT = 6.5f`，限幅过大会导致电流畸变，也会产生噪音。

## 三、进阶优化：PWM与ADC采样同步（根治纹波）
你现在用的是ADC连续自由采样，采样点随机落在PWM周期任意位置，很容易采到PWM开关瞬间的尖峰噪声，导致采样值波动大。

工业级FOC的标准做法是：
- **PWM下溢中断触发ADC采样**，在每个PWM周期的正中间采样，此时相电流最平稳、噪声最小
- 采样完成后再执行电流环计算，保证一个PWM周期更新一次，时序严格同步

这个改动稍大，等前面的基础问题都解决后再做，平顺度和噪音会有质的提升。

### 直接结论
1. 大家常说的「PWM下溢中断触发ADC采样」，**默认是针对中心对齐（上下计数）PWM**的，不是你现在的向上计数模式。
2. 向上计数模式下，**计数归0的时刻绝对不能用来触发采样**——此时刚好是MOS管开关、占空比刷新的瞬间，电流尖峰最大，采到的全是噪声，正是你“吱吱”啸叫的重要来源。
3. 做FOC最推荐的做法：把PWM改成**中心对齐（向上-向下计数）模式**，然后在「计数器回到0（下溢）」的时刻触发ADC，这是工业级FOC的标准方案。

---

## 一、两种计数模式的采样时机原理
### 1. 中心对齐模式（FOC标准用法，强烈推荐）
计数轨迹：`0 → 周期最大值 → 0`，一个完整PWM周期内计数器先增后减。
- **下溢事件**：计数器从1减到0的时刻
- **上溢事件**：计数器加到周期最大值的时刻

这两个时刻都是PWM占空比的**正中点**：此时上下桥臂都没有开关动作，相电流纹波处于平稳的波峰/波谷，开关尖峰已经完全消失，是采样的最佳时机。

行业里常说的「下溢触发ADC」，就是特指这个模式下的计数归0事件，采样点刚好对准每个PWM周期的中点，采到的值最接近真实的平均电流。

### 2. 向上计数模式（单边沿对齐，不推荐用于FOC）
计数轨迹：`0 → 周期最大值 → 瞬间跳回0`
- 计数归0的时刻：刚好是PWM周期刷新、占空比更新、MOS管切换的时刻，di/dt尖峰最大，采样值噪声极其严重。
- 计数到最大值的时刻：马上就要跳回0，同样紧邻开关动作点，也不是最佳采样点。

如果坚持用向上计数，最优采样点是**周期中后段、离所有开关沿最远的位置**，一般需要用「比较匹配事件」专门设一个触发点，而不能直接用溢出/更新中断。

---

## 二、为什么中心对齐+下溢触发是FOC标配
1. **采样精度最高**：中点采样刚好采到电流纹波的平均值，最接近真实的直流分量，采样结果噪声最小。
2. **控制时序固定**：采样完成后立刻计算电流环、更新占空比，下半个周期刚好生效，控制延迟固定为1/2个PWM周期，环路稳定性最好。
3. **电机噪音更低**：中心对齐PWM的共模噪声和电流谐波天然比单边沿小，电机运行更平顺。

---

## 三、ESP32 MCPWM 对应的实操建议
你用的是ESP32平台，MCPWM外设原生支持中心对齐模式和硬件触发ADC，不需要CPU手动干预，时序精度最高：
1. **将定时器改为上下计数模式**
   ESP-IDF中配置 `counter_mode = MCPWM_TIMER_COUNT_MODE_UP_DOWN`。
2. **选择硬件触发事件**
   选用 `MCPWM_TIMER_EVENT_ZERO`（定时器计到0，即下溢）作为ADC的触发源。
3. **走硬件触发链路**
   通过MCPWM的同步触发接口，让PWM事件**直接硬件触发ADC开始转换**，全程不经过CPU，触发延迟只有几百纳秒，没有抖动。
4. **ADC+DMA搬运数据**
   ADC转换完成后通过DMA自动把结果搬进内存，再通过中断通知CPU执行Clark/Park变换和PID计算。

### 特别提醒
不要在PWM中断服务函数里手动启动ADC采样。中断响应有几微秒的抖动，这点偏差就可能刚好采到开关尖峰上。**硬件PWM直接触发硬件ADC**，才是消除采样噪声的关键。
