### 一、先搞定闭环前提：3项基础校验（必须先做，否则调PID全是玄学）
这一步对应DengFOC里的`DFOC_alignSensor`+电流校准，是负反馈能工作的根基，也是你之前Iq符号飘忽、数值乱跳的根源。

#### 1. 确认反馈极性：保证是负反馈
电流闭环的核心是**负反馈**，极性反了就会变成正反馈，直接电流拉满、飞车炸管。
验证方法（用你代码里的开环模式）：
1. 把闭环开关改成`#if 0`，强制开环输出，固定 `Uq=2V，Ud=0V`；
2. 电机堵转或低速旋转，观察Park输出的Iq：
   - 正确状态：Uq为正，Iq也为正；Uq增大，Iq同步增大；
   - 如果极性相反：要么电角度统一加负号，要么电流采样系数取反，二选一即可。

对应你代码里的`park_tansform`输出，必须保证「Uq正向增加 → Iq正向增加」，这是PID能正常工作的第一原则。

#### 2. 校准零位：消除Id/Iq耦合
编码器零位不准会导致d/q轴错位：你给Uq的电压，会有一部分跑到Id轴上，两个环互相干扰，怎么调都稳不住。
验证+校准方法：
1. 开环输出 `Ud=2V，Uq=0V`，此时电机应被锁死在d轴方向；
2. 观察Park结果：理想状态下Id最大、Iq接近0；
3. 如果Iq数值很大，微调`theta_e_offset_mech`零位偏移，直到Iq降到最小（±0.02A以内）。

你代码里注释掉的直流对齐校准逻辑建议恢复，上电自动校准一次零位，这是FOC的标准操作。

#### 3. 确认电流幅值匹配物理规律
你之前堵转时Uq=3.5V对应Iq≈0.49A，反推相电阻≈7.1Ω，符合小电机参数，说明电流换算系数是对的。
额外确认：三相电流满足 `Ia+Ib+Ic≈0`，误差在5%以内，说明采样通道和极性都没问题。

### 二、核心修正：把PI控制器调对，消除稳态误差
你现在代码里 `ki = 0.0f`，只有纯比例控制，这就是你担心「永远达不到期望值」的直接原因。
- 纯P控制：永远存在稳态误差，误差×P系数=输出，误差不可能归零；
- 加入积分项I：只要有误差，积分就会持续累加，不断调整Uq，直到稳态误差几乎为0。

#### 1. 给你适配的初始PI参数（20KHz控制周期）
基于你的电机电阻约7Ω、控制周期50μs，给一组保守的起步参数，不会炸机：
```c
// ========== Iq 电流环 ==========
curent_loop_iq_pid.kp = 8.0f;    // 比例系数，你之前20太猛，先从小的来
curent_loop_iq_pid.ki = 200.0f;  // 积分系数，单位 1/s，每秒累加误差
curent_loop_iq_pid.kd = 0.0f;    // 电流环一般不用D项，容易放大噪声

// ========== Id 电流环 ==========
curent_loop_id_pid.kp = 6.0f;    // d轴响应稍慢，参数略小
curent_loop_id_pid.ki = 150.0f;
curent_loop_id_pid.kd = 0.0f;
```

⚠️ 关键核对：你的`vfoc_pid_calt`函数里，积分项是否乘了控制周期`pid_dt`？
- 如果积分公式是 `integral += ki * error * dt`，上面的参数直接可用；
- 如果是 `integral += ki * error`（没乘dt），ki要缩小1000倍（比如ki=0.01），否则积分会直接爆掉。

DengFOC的PID是带`Ts`周期计算的标准实现，和第一种写法一致。

#### 2. 必须开启积分限幅，防止积分饱和
堵转或启动时误差很大，积分项会越积越多，松开后电流会严重超调，这是新手最容易踩的坑。
你代码里已经定义了`ki_integral_min/max`，务必确保PID函数里真的对积分项做了限幅：
- 推荐限幅值：设为输出限幅的70%，比如UQ_LIMIT=6.9V，积分限幅就设±5V；
- 进阶可以加「积分退饱和」：输出限幅生效时，停止积分累加。

#### 3. 输出限幅匹配硬件能力
12V母线SVPWM的最大电压矢量幅值约为 `12 / sqrt(3) ≈ 6.93V`，所以Ud和Uq的合向量不能超过这个值。
简单做法：Uq、Ud各自限幅到±6V，留足余量，避免过调制导致波形失真。

### 三、打通闭环回路：确保数据流完整正确
你的代码框架其实已经搭对了，但有几个细节会导致闭环断链，对照修正：

#### 1. 确认PID输出真的送到了SVPWM
你代码里的路径是对的：
```c
curent_loop_park.Uq = curent_loop_iq_pid.pid_out;
curent_loop_park.Ud = curent_loop_id_pid.pid_out;
vfoc_set_svpwm(curent_loop_park.Uq, curent_loop_park.Ud, MOTOR_DRV_VBUS);
```
对应DengFOC的核心逻辑：`误差 → PID → Uq → 反Park → 反Clark → PWM输出`，完全一致。
确认点：`vfoc_set_svpwm`内部是用传入的Ud/Uq做反变换，没有写死其他值。

#### 2. 把角度读取移到FOC任务内，和电流同时刻采样
你之前说角度在Core1的1KHz任务里读取，这是Park变换失真的核心原因——用1ms前的角度解当前的电流，相位完全错位。
**必须修改**：在`vfoc_curent_loop`函数里、调用`park_tansform`之前，**立刻读取一次编码器角度**，保证电流和角度是同一时刻的。
如果是AS5600这类I2C编码器，20KHz读取可能偏慢，可以降到10KHz，也远比1KHz好。

#### 3. 滤波强度适中，不要过度延迟
你现在低通滤波alpha=0.4，20KHz采样下时间常数约75μs，是合理的。
- 如果闭环震荡：把alpha调到0.2~0.3，滤波更强；
- 如果响应太慢：把alpha调到0.5，更跟手。
DengFOC用50ms大时间常数滤波，是因为它采样异步、噪声大，你同步采样后不需要这么强的滤波。

### 四、分步调试流程（照着做，一次就能跑通）
按照「开环→单环→双环→动态」的顺序，循序渐进，避免直接炸机。

#### 第一步：开环基线验证
1. 强制开环，固定Uq=2V、Ud=0；
2. 确认Iq反馈平稳、极性正确、幅值符合电阻计算值；

#### 第二步：单Iq环闭环调试

2. Iq给定设为0.1A（小电流，安全），先只开P项（Ki=0）；
3. 看实际Iq能不能跟上给定，记录稳态误差有多大；
4. 慢慢加大Ki，直到稳态误差接近0，且没有持续震荡。

#### 第三步：加入Id环

#### 第四步：动态性能验证
1. 把Iq给定从0.1A阶跃到0.5A，看电流上升速度和超调量；
2. 堵转→松开→再堵转，看电流能不能快速恢复稳定；
3. 震荡就减小P/I，响应慢就加大P/I，逐步优化。
