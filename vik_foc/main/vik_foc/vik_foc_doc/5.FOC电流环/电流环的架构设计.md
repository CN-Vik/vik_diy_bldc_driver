## 我建议最终架构

```
              MCPWM TEZ ISR (40kHz)
                     │
               分频(÷4)
                     │
                     ▼
         vTaskNotifyGiveFromISR()
                     │
                     ▼
          电流环Task（10kHz，最高优先级）
                     │
         ┌───────────┴────────────┐
         │                        │
         ▼                        ▼
    ADC采样                  获取最新角度
         │                        │
         └───────────┬────────────┘
                     ▼
               Clarke变换
                     ▼
                Park变换
                     ▼
                 Id/Iq PI
                     ▼
              反Park变换
                     ▼
                SVPWM计算
                     ▼
           更新PWM Compare
```

整个FOC全部在一个Task里完成。

# 为什么推荐这样？

因为FOC本来就是一个完整的控制链。

例如：

```
Ia Ib Ic

↓

Clark

↓

Park

↓

Id Iq

↓

PI

↓

Ud Uq

↓

Inv Park

↓

SVPWM

↓

PWM
```

这些步骤之间的数据都是连续的。

例如：

```c
current

↓

i_alpha

↓

i_beta

↓

id

↓

iq

↓

ud

↓

uq

↓

duty
```

如果拆成多个Task：

```
Current Task

↓

Queue

↓

FOC Task

↓

Queue

↓

PWM Task
```

会产生：

* Task切换
* Queue复制
* 数据同步
* 延迟

这些都是没有意义的。

---

# 工业FOC也是这样

例如TI C2000：

```
ADC ISR
{
    read_current();

    read_encoder();

    clarke();

    park();

    current_PI();

    inv_park();

    svpwm();

    update_pwm();
}
```

全部在一个ISR里完成。

STM32很多FOC库也是类似：

```
ADC Inject ISR

↓

FOC_CurrController()

↓

SVPWM()

↓

Update Compare
```

不是一个函数一个任务。

---

# 你的ESP32适合这样吗？

非常适合。

你的PWM：

```
40kHz
```

但是：

```
div == 4
```

所以：

```
FOC

10kHz

100us
```

ESP32：

```
240MHz
```

100us里面：

大约：

```
24000个CPU周期
```

实际上远不止，因为240MHz×100us=24000 cycles。

而FOC运算：

```
Clark

Park

PI

SVPWM
```

加起来通常几百到几千个CPU周期（取决于是否使用硬件FPU、三角函数实现等）。

也就是说：

```
100us

绰绰有余。
```

# 我建议任务这样划分

### Task1：Current FOC Task（最高优先级）

```
PWM ISR

↓

Notify

↓

Current Task

↓

ADC

↓

FOC

↓

PWM
```

里面完成：

```c
current_read();

theta = g_motor_angle;

clarke();

park();

id_pi();

iq_pi();

inv_park();

svpwm();

set_pwm();
```

全部放一起。

---

### Task2：Encoder Task

单独负责：

```
I2C

↓

AS5600

↓

g_motor_angle
```

例如：

```
5kHz
```

或者：

```
2kHz
```

都可以。

---

### Task3：Log Task

负责：

```
printf

UART

LOG

OLED
```

千万不要影响FOC。

# 我觉得你现在工程最合理的结构

```
                    MCPWM(40kHz)
                         │
                  TEZ ISR(40kHz)
                         │
                     div == 4
                         │
                         ▼
                  FOC Task(10kHz)
                         │
        ┌──────────────────────────────────────┐
        │ ADC采样                              │
        │ 获取最新角度(g_motor_angle)          │
        │ Clarke                              │
        │ Park                                │
        │ Id PI                               │
        │ Iq PI                               │
        │ 反Park                              │
        │ SVPWM                               │
        │ Update Compare                      │
        └──────────────────────────────────────┘

──────────────────────────────────────────────

             Encoder Task(5kHz)
                    │
               I2C读取AS5600
                    │
          g_motor_angle = 最新值

──────────────────────────────────────────────

              Log Task(100Hz)
```

**这是我最推荐给你当前ESP32工程的架构**。

这样做有几个优势：

* **时序清晰**：一个PWM节拍对应一次完整的电流环控制。
* **数据一致**：ADC、电流计算、SVPWM使用的是同一控制周期的数据。
* **实时性最好**：没有多个实时任务之间的同步和切换开销。
* **后续扩展方便**：以后加入弱磁控制、MTPA、观测器等，也都自然放在这个电流环任务里。
