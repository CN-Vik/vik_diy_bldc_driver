### 为什么要对齐零点？（通俗解释）

你的编码器（比如AS5600）安装在电机屁股上。上电那一刻，编码器说：“我现在读数是 120 度”。
但是芯片不知道这个 120 度对应电机内部磁铁的什么位置。
FOC 算法就像射箭，**d轴是靶心，q轴是旁边垂直的位置**。如果你不知道零点在哪里，芯片以为自己在往 q 轴（发力方向）射箭，实际上箭全部射到了 d 轴（卡死方向）或者乱射一通。这就是为什么你给 q 轴电流，电机却乱抖发烫的原因。

我们需要找到一个“机械角度”**，在这个角度下，磁铁刚好和定子的A相线圈完全对齐（也就是**电角度的 0 度）。这个机械角度就是你的 `theta_e_offset_mech`。

---

### 超简单：零点校准 4 步操作法

我们不需要高大上的仪器，直接用代码把电机“拉”到零点。

#### 第一步：写一段临时的“强拉校准”代码

在你上电初始化、或者还没进入 FOC 电流环主循环之前（也可以直接在你的 `vfoc_curent_loop` 里临时改写），**强行给电机灌一个定方向的电压，并且把电角度死死写成 0**。

把代码临时改成这样：

```c
// 1. 强行给 d 轴发一个开环电压（比如 2V 到 3V，根据你电机内阻来，能吸住就行，别太高免得发烫）
curent_loop_park.Ud = 2.5f; 
curent_loop_park.Uq = 0.0f; // q 轴不发力

// 2. 核心：强行在送入 SVPWM 之前，把电角度写死为 0 弧度！
// 绕过你那个 get_vfoc_theta_e_rad 函数，直接给后续算法灌 0
float test_elec_deg_rad = 0.0f; 

// 3. 把这个 0 弧度和上面的 Ud/Uq 送给你的 SVPWM 
// 类似这样：set_SWM(curent_loop_park.Uq, curent_loop_park.Ud, test_elec_deg_rad);

```

#### 第二步：上电观察，读取机械角度

1. 把上面这段代码烧录进去，通电。
2. 你会听到电机“咔哒”一声，转子猛地吸向一个固定位置，然后死死不动了。
3. **此时此刻，电机内部停下来的这个位置，就是物理上的“电角度 0 度”！**
4. 这时候，用 `printf` 打印出你当前 AS5600 读到的**真实机械角度** `m_angle`（比如串口打印出来连续显示的数值是 `145.8` 度）。

#### 第三步：把这个宝贵的数字写进代码

这个 `145.8` 就是你电机的专属密码（每个电机、每次重装编码器都不一样）。
把它填到你的结构体初始化里，或者直接在代码里做减法：

把你的 `get_vfoc_theta_e_rad` 函数改回闭环状态，把 0 改成你测出来的数字：

```c
float get_vfoc_theta_e_rad(float m_angle)
{
    float elec_deg;

    // 重点：把刚才测到的 145.8 减掉！
    // 这样当电机回到刚刚那个吸住的位置时，(145.8 - 145.8) * 极对数 = 0 度，电角度就完美对齐了！
    elec_deg = (m_angle - 145.8f) * vfoc_dt.motor_par.pole_pairs;

    /* 后面的限制 0~360 和转弧度代码保持不变 */
    while (elec_deg >= 360.0f) elec_deg -= 360.0f;
    while (elec_deg < 0.0f)   elec_deg += 360.0f;
    elec_deg = FOC_DEG_TO_RAD(elec_deg);
    
    vfoc_dt.motor_par.theta_e = elec_deg;
    return elec_deg;
}

```

#### 第四步：大功告成，去调 PI 吧！

把第一步加的临时代码删掉，恢复正常的 FOC 流程。
这时候，你的 FOC 坐标系就已经彻底和电机的物理世界对齐了。
