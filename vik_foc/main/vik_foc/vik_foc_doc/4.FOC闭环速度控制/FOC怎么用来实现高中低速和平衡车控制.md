没有一个全球统一标准说“多少 RPM 就一定是低速/中速/高速”。**电机高低中速通常是相对于这个电机自己的额定转速、最高转速、极对数、控制频率来定义的。**

但你现在学习 FOC，可以先用一个实用定义。

---

# 1. 最简单的 RPM 分段法

如果只按机械转速 `rpm` 来分，可以先这样理解：

```text
低速：0 ~ 100 rpm
中低速：100 ~ 300 rpm
中速：300 ~ 800 rpm
高速：800 rpm 以上
```

这其实和你代码注释里的思路接近：你代码里也写了低速稳定大概 `100~300rpm`，中速测试 `300~800rpm`，高速测试 `800~1300rpm`，并且中高速建议提高 FOC 控制频率。

对你现在这个学习阶段，可以先这么定：

| 档位     |        RPM 范围 | 特点                  |
| ------ | ------------: | ------------------- |
| 超低速/启动 |    0 ~ 30 rpm | 容易卡顿、齿槽感明显、速度计算不准   |
| 低速     |  30 ~ 120 rpm | 需要小 Uq、强滤波、软 PI     |
| 中低速    | 120 ~ 300 rpm | 比较容易稳定              |
| 中速     | 300 ~ 800 rpm | 需要更高 Uq，控制频率最好提高    |
| 高速     |    800 rpm 以上 | 角度延迟、反电动势、FOC频率影响明显 |

---

# 2. 更科学的定义：按电机额定转速百分比

比如一个电机最高能跑 `3000rpm`，那可以这么分：

```text
低速：0 ~ 20% 最大转速
中速：20% ~ 60% 最大转速
高速：60% ~ 100% 最大转速
```

举例：最大转速 3000rpm：

```text
低速：0 ~ 600 rpm
中速：600 ~ 1800 rpm
高速：1800 ~ 3000 rpm
```

如果另一个电机最高只能跑 1000rpm：

```text
低速：0 ~ 200 rpm
中速：200 ~ 600 rpm
高速：600 ~ 1000 rpm
```

所以不能只看绝对 RPM，要看电机本身能力。

---

# 3. FOC 里更应该看“电角速度”

FOC 不只是看机械 RPM，还要看电角速度。

公式是：

```text
机械转频 = rpm / 60
电角频率 = 机械转频 × 极对数
```

比如你的电机如果是 `7 对极`，那么：

```text
100 rpm:
机械转频 = 100 / 60 = 1.67 r/s
电角频率 = 1.67 × 7 = 11.7 Hz

1000 rpm:
机械转频 = 1000 / 60 = 16.67 r/s
电角频率 = 16.67 × 7 = 116.7 Hz
```

也就是说，同样是 `1000rpm`，极对数越多，FOC 看到的电角度转得越快，控制难度越高。

---

# 4. 为啥 FOC 更关心电角频率？

FOC 每次都要根据电角度计算：

```text
Park 变换
反 Park 变换
SVPWM
```

如果电角度变化太快，而你的 FOC 控制频率太低，就会出现：

```text
角度跟不上
Uq方向滞后
力矩变小
震动变大
高速失步
电机发热
```

你现在代码里 FOC 控制频率是：

```c
#define M0_FOC_CTRL_FREQ_HZ 1000
```

也就是 1kHz。

1kHz 对低速学习可以，但如果想稳定做几百 rpm 以上，后面最好提高到：

```text
中速：5kHz
高速：10kHz 或更高
```

# 5. 对你现在项目，我建议这样定义

你现在是学习 FOC，有 AS5600，VBUS 12V，先别按工业高速标准来。建议这样：

```text
低速档：30 ~ 120 rpm
中速档：120 ~ 500 rpm
高速档：500 ~ 1300 rpm
```

对应参数策略：

| 档位 |      RPM |     Uq限制 | PI风格              |
| -- | -------: | -------: | ----------------- |
| 低速 |   30~120 | 0.8~1.5V | Kp/Ki 小，滤波强       |
| 中速 |  120~500 | 1.5~3.0V | Kp/Ki 适中          |
| 高速 | 500~1300 | 3.0~5.0V | Uq更大，斜坡启动，FOC频率提高 |

# 6. 一句话总结

**RPM 的高低速没有绝对标准。**

对你当前 FOC 学习项目，可以先这么定：

```text
0~30 rpm：启动/超低速
30~120 rpm：低速
120~500 rpm：中速
500~1300 rpm：高速
```

更专业一点，要结合：

```text
电机最高转速
额定转速
极对数
FOC控制频率
编码器采样速度
母线电压 VBUS
```

你现在先把 `30~120rpm` 低速档调稳，再调 `120~500rpm` 中速档，最后再碰高速。

------
可以，**FOC 本身完全可以做 10000RPM**。很多电机产品就是 FOC 跑高速的。

但是要分清楚两句话：

```text
FOC 理论上可以做 10000RPM。
你现在这套代码/硬件状态，不建议直接上 10000RPM。
```

你当前代码里 FOC 控制频率还是 `1kHz`，代码注释里也写了：`300~800rpm` 建议提高到 `5kHz`，`800~1300rpm` 建议提高到 `10kHz` 并且必须斜坡启动。
所以 **10000RPM 肯定不是现在 1kHz 速度环/FOC 周期直接改目标值就能跑的。**

---

## 1. 10000RPM 到底有多快？

```text
10000 rpm = 每分钟 10000 转
          = 每秒 166.7 转
```

也就是机械转频：

```text
166.7 Hz
```

如果你的电机是 **7 对极**，那电角频率是：

```text
电角频率 = 机械转频 × 极对数
        = 166.7 × 7
        ≈ 1167 Hz
```

这意味着电角度每秒转 1167 圈。

你现在 FOC 控制频率是：

```text
1kHz = 每秒算 1000 次
```

如果 7 对极、10000RPM，电角频率已经约 1167Hz，**你的 FOC 一秒算 1000 次，连一个电周期采样一次都不够**。这样肯定会失控、抖动、尖叫、发热。

---

## 2. 做 10000RPM，需要多高的 FOC 控制频率？

经验上，FOC 控制频率最好至少是电角频率的 **10~20 倍以上**。

还是按 7 对极举例：

```text
10000rpm → 电角频率 ≈ 1167Hz
```

那么 FOC 控制频率建议：

```text
最低：1167 × 10 ≈ 11.7kHz
较好：1167 × 20 ≈ 23.3kHz
```

所以你要做 10000RPM，FOC 控制频率建议：

```text
20kHz 左右
```

最低也得：

```text
10kHz 以上
```

而不是现在的：

```text
1kHz
```

---

## 3. PWM 频率也要配合

你现在 PWM 定义是：

```c
#define M0_PWM_FREQ_HZ (40 *(1000))
```

也就是 40kHz PWM，这个频率本身还可以。

但是注意：如果你的 FOC 控制频率提高到 20kHz，PWM 是 40kHz，那相当于每 2 个 PWM 周期更新一次 FOC 输出，勉强可以。更理想是：

```text
PWM：40kHz
FOC控制：10kHz ~ 20kHz
速度环：500Hz ~ 1kHz
```

不要速度 PI 每 1ms 才算一次还想稳定 10000RPM。高速下速度环可以慢一点，但电角度更新/SVPWM 输出必须快。

---

## 4. AS5600 很可能是瓶颈

你现在用 AS5600 这种磁编码器学习 FOC 很合适，但要做 10000RPM，高速下有几个风险：

```text
1. I2C 读取速度可能不够
2. 角度数据有延迟
3. 磁铁偏心会导致角度周期性误差
4. 速度差分会很抖
5. 高速下角度延迟会变成电角度相位误差
```

在低速时，角度晚一点点问题不大。
但 10000RPM 时，电角度转得很快，角度延迟一点点，就可能变成很大的电角误差。

结果就是：

```text
Uq 本来应该垂直于转子磁场产生力矩
但因为角度滞后，Uq 方向偏了
力矩变小
电机发热
声音变大
高速上不去
甚至失步
```

所以 10000RPM 更适合用：

```text
高速编码器
ABI/ABZ 增量编码器
SPI 磁编码器
霍尔 + 估算
无感 FOC 观测器
```

AS5600 I2C 版本不太适合直接冲很高转速。

---

## 5. 12V VBUS 也可能不够

10000RPM 能不能跑，还取决于电机 KV 值。

简单理解：

```text
电机转速越高，反电动势越大
反电动势越大，需要的母线电压越高
```

如果你的电机 KV 比较低，12V 可能根本跑不到 10000RPM。
如果是高 KV 小电机，12V 可能可以。

所以不能只说 FOC 可不可以，要看：

```text
电机 KV
极对数
负载
母线电压 12V
驱动电流能力
编码器速度
FOC 控制频率
```

## 6. 你现在怎么一步步验证？

不要直接写：

```c
target_rpm = 10000;
```

正确路线是：

```text
500rpm
1000rpm
1500rpm
2000rpm
3000rpm
5000rpm
8000rpm
10000rpm
```

每一级都看：

```text
速度能不能稳

电机有没有发热
MOS 有没有发热
声音是否异常
速度反馈是否跳
电流是否过大
```

如果在 1000rpm 都已经：

```text

```

那就别继续往上加了。

## 7. 你现在代码要怎么改才有资格试高速？

### 先把 FOC 控制频率提高

比如先试 5kHz：

```c
#define M0_FOC_CTRL_FREQ_HZ        5000
#define M0_FOC_DT_S                (1.0f / M0_FOC_CTRL_FREQ_HZ)
#define M0_CTRL_ALARM_COUNT        (M0_CTRL_TIMER_RES_HZ / M0_FOC_CTRL_FREQ_HZ)
```

再试 10kHz：

```c
#define M0_FOC_CTRL_FREQ_HZ        10000
```

如果 CPU、I2C 读角度、SVPWM 计算都撑得住，再考虑更高。

---

### 速度环不要和 FOC 同频

比如：

```text
FOC/SVPWM：10kHz
速度 PI：500Hz 或 1kHz
```

也就是 FOC 每次都用最新角度输出 SVPWM，但速度 PI 每 10 次或 20 次更新一次 `Uq_target`。

---

### 目标速度必须斜坡

比如：

```c
#define RPM_RAMP_PER_S  1000.0f
```

目标速度每秒最多升 1000rpm。
从 0 到 10000rpm 至少 10 秒慢慢爬。

## 8. 最终结论

**FOC 可以做 10000RPM，但你现在这套学习代码不能直接做。**

要做 10000RPM，至少要满足：

```text
1. FOC 控制频率 ≥ 10kHz，最好接近 20kHz
2. PWM 频率 40kHz 左右可以继续用
3. 角度传感器必须足够快，AS5600 I2C 很可能成为瓶颈
4. 目标速度必须斜坡上升
5. Uq 限幅要逐步放开，但必须监控电流和发热
6. 12V 母线是否够，要看电机 KV
7. 先从 500、1000、2000、3000rpm 分级验证
```

你现在最现实的目标是：**先把 500~1000RPM 稳定跑起来，再把 FOC 频率提到 5kHz/10kHz。**
等 1000~3000RPM 都稳定，再谈 10000RPM。

---

# 1. FOC 一般是不是用来做中高速控制？

**是，中高速用得非常多。**

比如：

```text
电动车电机
平衡车
云台电机
机器人关节
水泵
风机
压缩机
电动工具
伺服电机
```

这些地方都可能用 FOC。

FOC 的优势是：

```text
1. 力矩平滑
2. 噪声小
3. 效率高
4. 高速性能好
5. 可以精确控制力矩/速度/位置
```

你现在用普通六步换相的话，中高速会有明显换相顿挫、电流波动、噪声。FOC 是让磁场连续旋转，所以更顺。

---

# 2. FOC 不是专门给高速用的

这个容易误解。

FOC 本质是：

```text
把三相电机变成“类似直流电机”来控制
```

也就是把电机电流分成两个方向：

```text
Id：励磁方向，通常 BLDC/PMSM 里设为 0
Iq：力矩方向，主要用来产生转矩
```

所以只要你能知道转子电角度，FOC 就能控制。

---

# 3. 为什么无感 FOC 中高速更常见？

如果是**无感 FOC**，也就是不用编码器，只靠电机反电动势估计角度。

问题是低速时：

```text
转速低
反电动势小
角度难估计
```

所以无感 FOC 低速很难做得好。

一般无感 FOC 启动流程是：

```text
先开环拖动
速度起来后
反电动势明显了
再切入闭环 FOC
```

所以你会看到很多无感 FOC 更偏中高速。

但你有 AS5600 编码器，所以不是无感。你可以低速闭环，只是速度采样、滤波、PI 参数要调好。

---

# 4. 平衡车一般用 FOC 哪些控制环？

平衡车不是简单速度控制。它核心是**姿态控制**。

一个两轮平衡车大概是这样的：

```text
IMU 姿态角
    ↓
平衡角度环
    ↓
速度/位置修正
    ↓
左右轮目标力矩/目标电流
    ↓
FOC 电流环
    ↓
SVPWM
    ↓
电机
```

更标准一点是：

```text
姿态环 → 速度环 → 电流/力矩环 → FOC
```

---

# 5. 平衡车最核心的环：姿态环

平衡车首先要解决的是：

```text
车身不能倒
```

所以最外层一定有一个姿态环。

IMU 测出来车身角度，比如：

```text
车身前倾 5°
```

控制器就要让轮子往前跑，把车身“接住”。

姿态环输入：

```text
目标角度：0°
实际角度：IMU 算出来的倾角
```

姿态误差：

```text
angle_err = target_angle - now_angle
```

姿态环输出一般是：

```text
目标力矩
或者目标速度
或者目标电流 Iq
```

对于平衡车，姿态环常用：

```text
PD
或者 PID
或者 LQR
```

初学阶段可以理解为：

```text
P：车身歪多少，就给多少纠正力
D：车身倒得有多快，就提前刹一下
```

这个 D 很重要，因为平衡车不是只看角度，还要看“倒下去的速度”。

---

# 6. 平衡车的速度环是干啥的？

如果只有姿态环，车能站住，但可能会慢慢漂走。

比如车为了保持平衡，会前后小幅运动。时间久了，它可能越跑越远。

所以要加速度环/位置环：

```text
轮子速度
或者轮子累计位移
```

作用是：

```text
让车不要一直往前跑
让车能听你的速度指令
让车能保持在原地附近
```

如果你想让平衡车原地站住：

```text
目标速度 = 0
实际速度 = 编码器测出来
```

速度环会修正姿态目标角度。

比如：

```text
车一直往前跑
速度环就让目标角度稍微向后
车自然减速回来
```

所以平衡车里经常有这种结构：

```text
速度环输出 → 目标倾角
姿态环输出 → 目标力矩/Iq/Uq
```

---

# 7. 平衡车的电流环/力矩环

真正产品级平衡车一般有电流采样。

标准 FOC 里面最内层是：

```text
Id 电流环
Iq 电流环
```

一般控制目标：

```text
Id = 0
Iq = 由上层控制器给出
```

因为：

```text
Iq 约等于力矩
```

所以平衡车需要快速控制力矩时，最好是：

```text
姿态环输出目标 Iq
Iq 电流环控制 Uq
SVPWM 输出三相 PWM
```

这样响应快、力矩准、抗扰动强。

---

# 8. 你现在这个阶段属于哪种？

你现在没有电流采样，所以你做的是简化版：

```text
速度误差 → PI → Uq → SVPWM
```

这个可以学习速度闭环，但它不是完整的伺服 FOC。

完整产品级应该是：

```text
速度误差 → PI → 目标 Iq
Iq误差 → PI → Uq
SVPWM
```

也就是：

```text
速度环不直接输出 Uq
速度环输出目标力矩/目标电流
电流环再输出 Uq
```

你现在是把电流环省略了，所以调起来会更敏感：

```text
Uq 大一点就冲
Uq 小一点又达不到速度
负载变化时速度容易掉
低速容易咔咔
```

这都是正常的。

# 9. 两轮平衡车一般完整控制框图

可以这样理解：

```text
遥控器/目标速度
        ↓
速度环 PI
        ↓
目标倾角
        ↓
姿态环 PD/PID
        ↓
目标 Iq / 目标力矩
        ↓
FOC 电流环 PI
        ↓
Ud / Uq
        ↓
SVPWM
        ↓
左右轮电机
```

如果还要转向：

```text
转向输入 → 左右轮差速
```

比如：

```text
左轮目标 = 基础力矩 - 转向量
右轮目标 = 基础力矩 + 转向量
```

# 10. 简化版平衡车可以怎么做？

如果你暂时没有电流采样，可以先做：

```text
IMU角度环 → Uq
```

或者：

```text
IMU角度环 → 目标速度
速度环 PI → Uq
```

更推荐学习路线：

## 第一阶段：单电机速度闭环

你现在正在做：

```text
目标 rpm → 速度 PI → Uq
```

把低速、中速、高速调稳。

---

## 第二阶段：单电机位置闭环

```text
目标角度 → 位置 PD → 目标速度
目标速度 → 速度 PI → Uq
```

这个比直接：

```text
位置误差 → Uq
```

更稳。

---

## 第三阶段：双电机同步速度控制

```text
左轮目标速度 → 左轮速度 PI → 左轮 Uq
右轮目标速度 → 右轮速度 PI → 右轮 Uq
```

调到两个轮子速度一致。

---

## 第四阶段：IMU 姿态环

```text
车身倾角误差 → 姿态 PD → 目标轮速/目标Uq
```

这时候才开始像平衡车。

---

# 11. 平衡车里哪些环最重要？

按重要程度：

```text
1. 姿态角环：保证不倒
2. 角速度阻尼：减少晃动，类似 D 项
3. 速度/位置环：保证不乱跑
4. 电流/力矩环：保证力矩响应快
5. 转向差速环：控制左右转
```

如果没有电流环，也能做简化版，但性能不如产品级。

---

# 12. 你现在该怎么连接到平衡车目标？

你现在先别急着上平衡车。你现在最该把这几个打牢：

```text
1. 单电机开环 FOC 稳定
2. 单电机速度闭环稳定
3. 单电机位置闭环稳定
4. 左右两个电机速度一致
5. IMU 姿态角稳定输出
6. 再做平衡控制
```

你目前正在第 2 步。

---

# 13. 最好记的总结

FOC 是底层电机控制方法，平衡车是在 FOC 上面加控制环。

```text
FOC 本身负责：让电机平滑、高效、快速地产生力矩
平衡车算法负责：决定什么时候给多少力矩
```

平衡车常见控制环：

```text
IMU姿态环：PD/PID
轮速环：PI
电流/力矩环：PI
转向环：差速控制
```

你现在做的速度 PI 是其中一环。后面真正做平衡车时，更核心的是：

```text
姿态环 + 速度环 + 左右轮差速
```

产品级则再加：

```text
Iq/Id 电流环
```

所以一句话：

```text
FOC 在中高速非常常见，但不是只能中高速；
平衡车主要用姿态环、速度环、电流/力矩环，FOC 是最底层的电机力矩执行器。
```
